Check the formatting of the Viash configs in a project and lint them
with [vlint](https://github.com/data-intuitive/viash-lint). Problems are
shown as annotations on the pull request.

vlint must be on the `PATH`. We recommend to use
[viash-actions/pro/setup-vlint](https://github.com/viash-io/viash-actions/tree/main/pro/setup-vlint)
before you run this action.

### Inputs available

- `format`: *(Optional)* Whether to check the formatting with
  `vlint format --check`. Default: `true`.
- `check`: *(Optional)* Whether to lint the configs with `vlint check`.
  Default: `true`.
- `project_directory`: *(Optional)* Path to the project directory. This
  is the directory where the project config `_viash.yaml` is located.
  Default: `.`.

## Usage

The data-intuitive/viash-lint repository is private, so a secret token
is required for access (here `VLINT_TOKEN`). Use
[`pro/setup-vlint`](../setup-vlint) to install vlint before you run
`pro/vlint`.

### Token required

By default (`on_missing_token: error`), the job fails when the
`VLINT_TOKEN` secret is not set. The `Setup vlint` step gives the error
“No token given” and the `vlint` step does not run. Use this when every
run must check the Viash configs and you expect the token to be set.
**NOTE:** Secrets are not available in pull request workflows from
forks, so this will fail for those workflows.

``` yaml
name: vlint

on:
  push:
    branches:
      - main
  pull_request:

permissions:
  contents: read

jobs:
  vlint:
    runs-on: ubuntu-latest

    steps:
    - name: Check out repository
      uses: actions/checkout@v6

    - name: Setup vlint
      uses: viash-io/viash-actions/pro/setup-vlint@v6
      with:
        token: ${{ secrets.VLINT_TOKEN }}

    - name: Format and lint Viash configs with vlint
      uses: viash-io/viash-actions/pro/vlint@v6
```

### Optional token

With `on_missing_token: skip`, the job does not fail when the
`VLINT_TOKEN` secret is not set. Use this for situations where the token
may not be available but you don’t want to see a failed job. The two
examples below show different ways to implement this which show
different output in GitHub.

#### One job

Th simplest way to skip the `vlint` step is to check for the token in
the `Setup vlint` step and skip the `vlint` step when it is not set.
With this approach, a notice and a line in the job summary say that the
configs were not checked but the job still shows as successful in the
pull request checks. Use the two-job approach below if you want the
`vlint` job to show as skipped in the pull request checks.

``` yaml
name: vlint

on:
  push:
    branches:
      - main
  pull_request:

permissions:
  contents: read

jobs:
  vlint:
    runs-on: ubuntu-latest

    steps:
    - name: Check out repository
      uses: actions/checkout@v6

    - name: Setup vlint
      id: setup-vlint
      uses: viash-io/viash-actions/pro/setup-vlint@v6
      with:
        token: ${{ secrets.VLINT_TOKEN }}
        on_missing_token: skip

    - name: Format and lint Viash configs with vlint
      if: steps.setup-vlint.outputs.installed == 'true'
      uses: viash-io/viash-actions/pro/vlint@v6
```

#### Two jobs

This approach uses a separate job to check that the token is available
and skip the `vlint` job when it is not set. Because the whole `vlint`
job is skipped, a skipped check is visible in the pull request checks
summary.

``` yaml
name: vlint

on:
  push:
    branches:
      - main
  pull_request:

permissions:
  contents: read

jobs:
  check-token:
    runs-on: ubuntu-latest
    outputs:
      available: ${{ steps.check.outputs.available }}

    steps:
    - name: Check for VLINT_TOKEN
      id: check
      env:
        VLINT_TOKEN: ${{ secrets.VLINT_TOKEN }}
      run: |
        if [ -z "$VLINT_TOKEN" ]; then
          echo "::notice title=vlint skipped::No VLINT_TOKEN secret is set."
          echo "available=false" >> "$GITHUB_OUTPUT"
        else
          echo "available=true" >> "$GITHUB_OUTPUT"
        fi

  vlint:
    needs: check-token
    if: needs.check-token.outputs.available == 'true'
    runs-on: ubuntu-latest

    steps:
    - name: Check out repository
      uses: actions/checkout@v6

    - name: Setup vlint
      uses: viash-io/viash-actions/pro/setup-vlint@v6
      with:
        token: ${{ secrets.VLINT_TOKEN }}

    - name: Format and lint Viash configs with vlint
      uses: viash-io/viash-actions/pro/vlint@v6
```
